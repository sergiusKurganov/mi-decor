# CLAUDE.md

Сайт студии декораторов «Мы.Decor» (`mi-decor.art`): статика на Astro, четыре страницы,
без бэкенда. Выкладывается на GitHub Pages.

**Перед работой прочитай [README.md](README.md)** — устройство, структура файлов и
команды. Технические решения и их причины — в [PLAN.md](PLAN.md), открытые вопросы
к владельцу — в [BUGS.md](BUGS.md).

## Как здесь устроено

```
src/
  data/          весь контент и вся геометрия — правки текста только здесь
  layouts/       Base.astro: head, мета, шапка, футер
  components/    SiteHeader, SiteFooter
  pages/         по файлу на страницу + sitemap.xml
  lib/           placement, optimize, images, rich, paths
  styles/        tokens, base, placed, fonts (генерируется)
  assets/        stickers, clients, team, icons
public/          шрифты с лицензией, favicon, og-картинка, CNAME
tools/           замер, сборка шрифтов и og, сервер для тестов, чистка сборки
tests/           скриншот-тесты и доступность; tests/baseline — эталон
```

**Модель координат.** Макет построен на пяти центрированных контейнерах:
1200 / 960 / 640 / 480 / 320 (см. `src/data/layout.json`). Внутри контейнера координаты
элемента постоянны, поэтому позиция считается как `calc(50% - design/2 + x)`. Абсолютный
`left`, снятый замером, писать нельзя: совпадёт только на той ширине, где мерили.
Механизм — классы `.board` и `.placed` из `src/styles/placed.css`, переменные отдают
`spotVars()` / `boardVars()` из `src/lib/placement.ts`, числа приходят из `src/data`.

По брейкпоинтам меняется почти всё оформление, а не только позиция: выключка, размер
шрифта, межстрочное, разрядка, регистр, кадрирование фона, цвет подложки. Всё это
живёт в данных.

## Правила

- **Геометрию не подгоняем на глаз.** Сначала замер (`tools/measure.mjs`), потом CSS
  под полученные числа, потом сверка той же командой.
- **Проверять тестами, а не на слово.** После правки — `npm run test:visual`. Задача
  не закрыта, пока снимки не зелёные во всех пяти разрешениях.
- **Адреса не меняем.** `/`, `/commande`, `/project`, `/contact` должны продолжать
  работать: на них есть внешние ссылки.
- **Контент — в данных.** Тексты, телефоны, имена, логотипы правятся в `src/data`,
  разметку для этого трогать не нужно. Ничего не выдумывать и не переписывать
  «покрасивее» без просьбы.
- **Свои имена.** Классы, файлы и данные называем осмысленно. Машинных
  идентификаторов — наборов цифр и шестнадцатеричных блоков — быть не должно.
- **Не тащить зависимости без нужды.** Сайт на четыре страницы текста и картинок.
  Прежде чем добавлять библиотеку — спросить.
- **Вопросы к владельцу — в `BUGS.md`,** а не молчаливая правка внешнего вида.
- **Ничего не удалять пачкой.** Если файл кажется лишним — сначала проверить, что на
  него никто не ссылается. Для сборки это делает `tools/prune.mjs`.
- **Коммиты по-русски, в императиве, с префиксом:** `feat:`, `fix:`, `refactor:`,
  `chore:`, `docs:`, `test:`, `perf:`. Мелкими шагами, чтобы каждый коммит оставлял
  сайт рабочим.
- **Ветки.** Работа идёт в `feature/<что-делаем>` от `main` и вливается обратно.
  Push в `main` запускает выкладку на прод, поэтому напрямую туда не коммитим.

## Команды

Версия Node закреплена в `mise.toml`, поэтому команды — через `mise exec --`.

```bash
npm run dev              # разработка
npm run build            # сборка в dist + чистка неиспользуемых файлов
npm run serve:dist       # посмотреть собранный сайт на localhost:8765
npm test                 # всё: скриншоты и доступность
npm run test:visual      # 20 снимков: 4 страницы × 5 разрешений
npm run test:a11y        # axe + проверка клавиатуры
npm run test:report      # отчёт «ожидали / получили / diff»
npm run baseline         # перезаписать эталон — только осознанно
npm run fonts            # перекачать шрифты и лицензию
```

Сервер из `serve:dist` сам достраивает `.html`, как это делает хостинг, поэтому чистые
адреса работают и локально.

Сверить геометрию числами:

```bash
node tools/measure.mjs /contact.html 1440 '.card'
node tools/sweep.mjs /index.html '.text'     # по всему диапазону ширин
node tools/weigh.mjs dist /index.html 1440   # сколько качает браузер
```

Перезапись эталона стирает то, с чем сравниваемся. Красный тест почти всегда означает
баг в вёрстке, а не устаревший эталон.

## Грабли

- `astro dev` и `astro preview` уходят в фон и держат реестр серверов, поэтому
  Playwright считает их упавшими, а запрошенный порт игнорируется. Для тестов и
  просмотра — `tools/serve.mjs`. Если порт занят непонятно кем: `npx astro dev stop`
  и `npx astro preview stop`.
- **Границы брейкпоинтов не всегда совпадают с контейнерами:** боковые отступы шапки
  переключаются на 1201px, ширина текстового блока контактов — тоже на 1201, а бургер
  появляется на 980. Проверять проходом по диапазону: `tools/sweep.mjs`.
- **`display: inline-block` не годится, когда нужна точная высота коробки:** к строке
  добавляется место под выносные элементы шрифта, и блок уезжает на пару пикселей.
  Флекс даёт предсказуемый размер.
- **Фоновые картинки не попадают в `document.images`** — если ждать только теги `img`,
  снимок можно сделать раньше, чем фотографии появятся.
- **Во время сборки `Astro.url.pathname` содержит `.html`.** Для адресов и активного
  пункта меню использовать `cleanPath()` из `src/lib/paths.ts`.
- **`stats()` в sharp считает по исходному файлу и игнорирует `extract()`** — числа
  получаются от всей картинки. Для проверки участка вырезать в файл и смотреть глазами.
- Не подгонять цифры под тест: если что-то разошлось, сначала замерить обе версии
  и понять причину.
