# Мы.Decor

Сайт студии декораторов «Мы.Decor» — [mi-decor.art](https://mi-decor.art).
Статика на Astro, четыре страницы, без бэкенда.

## Страницы

| Адрес | Заголовок | Что там |
|---|---|---|
| `/` | О нас | Коллаж из 16 стикеров, текст о студии, кнопка на контакты |
| `/commande` | Команда | 16 карточек: фото, имя, должность, специализация, стаж |
| `/project` | Проекты | Заголовок и стена из 13 логотипов клиентов |
| `/contact` | Контакты | Два телефона, телеграм |
| `/404` | Не найдено | Страница с навигацией |

`/about` отдаёт редирект на главную.

Палитра: чёрный фон `#0c0a0a`, розовый акцент `#ff6cb5`. Шрифт Roboto своими файлами
в `public/fonts` — под SIL Open Font License 1.1, текст лицензии лежит рядом
в `OFL.txt`.

## Из чего собрано

```

    team.json    карточки команды по блокам
    projects.json  логотипы клиентов
    contact.json, footer.json, site.json
  layouts/       Base.astro — head, мета, шапка, футер
  components/    SiteHeader, SiteFooter

```

## Модель координат

Макет построен на пяти **центрированных контейнерах**: 1200 / 960 / 640 / 480 / 320.
Внутри контейнера координаты элемента постоянны, поэтому позиция считается как
`calc(50% - design/2 + x)` — и остаётся верной на любой ширине окна, а не только
в тех точках, где её проверяли. Ничего не масштабируется: размер шрифта одинаков
на всех ширинах.

Числа приходят из `src/data` инлайновыми переменными, а медиазапросы в
`src/styles/placed.css` выбирают нужный набор. По брейкпоинтам меняется почти всё
оформление — не только позиция и размер, но и выключка, размер шрифта, межстрочное,
регистр, кадрирование фона и цвет подложки. Поэтому эти свойства лежат в данных,
а не в стилях.

Весь механизм — классы `.board` (контейнер со своей высотой) и `.placed` (элемент
с координатами) плюс `spotVars()` / `boardVars()` из `src/lib/placement.ts`.

Подробнее о решениях и их причинах — в [PLAN.md](PLAN.md).

## Как менять

**Текст, телефоны, состав команды, логотипы** — в `src/data/*.json`. Разметку трогать
не нужно.

**Позицию элемента** — там же, в его `at`: свой набор координат на каждый брейкпоинт.

**Картинки** — положить в `src/assets/{stickers,clients,team}` и указать имя файла
в данных. Размеры и форматы считаются на сборке: `srcset` и `sizes` собираются из тех
же данных, поэтому браузер качает ровно нужный файл.

**Шрифты** — `npm run fonts` перекачает Roboto, обновит `src/styles/fonts.css`
и заберёт свежий текст лицензии.

**Картинку для соцсетей** — `node tools/build-og.mjs`.

## Команды

```bash
npm run dev              # разработка
npm run build            # сборка в dist + чистка неиспользуемых файлов
npm run serve:dist       # посмотреть собранный сайт на localhost:8765
npm test                 # всё: скриншоты и доступность
npm run test:visual      # 20 снимков: 4 страницы × 5 разрешений
npm run test:a11y        # axe + проверка клавиатуры
npm run test:report      # отчёт «ожидали / получили / diff»
npm run baseline         # перезаписать эталон — только осознанно
```

Версия Node закреплена в `mise.toml`, поэтому команды удобно звать через
`mise exec -- npm …`.

Замерить собранный сайт:

```bash
node tools/measure.mjs /commande.html 1440 '.name' '.photo'
node tools/sweep.mjs /index.html '.text'     # по всему диапазону ширин
node tools/weigh.mjs dist /index.html 1440   # сколько качает браузер
```

## Как выкладывается

Каждый push в `main` запускает `.github/workflows/deploy.yml`: сборка и выкладка на
GitHub Pages. Домен привязан файлом `public/CNAME`, A-записи домена смотрят на адреса
GitHub Pages, `www` — CNAME на `sergiuskurganov.github.io`.

## Что важно знать

- Собранный сайт не тянет ничего со сторонних доменов: шрифты свои, JS-бандлов нет
  вовсе — на выходе статика.
- Сколько качает браузер: главная 289 КБ (на телефоне 188), «Команда» 400 КБ,
  «Проекты» 211 КБ, «Контакты» 133 КБ.
- Проверки: 20 скриншотов в пяти разрешениях и прогон axe по всем страницам.
- Открытые вопросы к владельцу — в [BUGS.md](BUGS.md).
